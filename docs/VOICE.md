# Voz local

El canal de voz usa un protocolo JSONL sobre stdio y no abre sockets. El dictado se activa manteniendo pulsado **MIC** y se detiene al soltarlo; la transcripción local se coloca en el campo de texto para que el usuario la revise antes de enviarla. En Ajustes se elige con un diálogo nativo la carpeta de un modelo faster-whisper local con `model.bin` y `config.json`. El código carga el modelo con `local_files_only=True`: si no existe o faltan dependencias, informa el error y no descarga modelos.

El sidecar puede iniciar sin el modelo Piper para permitir dictado independiente. La voz de salida requiere Piper y el modelo `.onnx` configurado en la ruta local de voces. El procesamiento real de micrófono y Piper requiere una prueba manual en Windows con hardware de audio. La activación siempre escuchando por frases como «Bit, ¿estás ahí?» y por aplauso queda pendiente: antes de habilitar micrófono continuo hay que medir CPU en reposo, falsos positivos y aciertos en este equipo.

Cuando la voz está activada, Bit inicia Piper mientras el modelo genera la respuesta para que la carga inicial se solape con ese tiempo y el audio pueda empezar antes de que el sidecar esté frío. Una respuesta nueva reemplaza la voz pendiente y limpia el audio anterior ya programado, para que no se mezclen mensajes de turnos distintos. La cola prepara una versión hablable independiente del texto del chat: omite bloques y fragmentos de código, enlaces URL, marcas Markdown y puntuación/símbolos no aptos para lectura, y conserva la explicación legible. También antepone el nombre preferido guardado en Ajustes a cada respuesta hablada, limpiando caracteres no aptos para lectura y salvo que el texto ya empiece con un saludo dirigido por ese nombre. Si la respuesta solo contiene código, Bit avisa que puede consultarse en el chat en vez de leerlo en voz alta. La cola divide el texto preparado por oración, permite vaciar la cola al detectar interrupción y mantiene el endpointing VAD entre 500 y 700 ms. `Porcupine` no forma parte del diseño; el wake word recomendado es “Oye Bit”.

La síntesis Piper usa un ritmo moderadamente pausado (`length_scale=1.12`) y valores de ruido reducidos para una entrega serena, pulida y articulada. Es un perfil original de asistente: no imita una voz de película. Estos controles cambian el ritmo y la estabilidad, no la identidad ni el tono fundamental de la voz; para cambiar el timbre hace falta elegir otro modelo local, con permiso del usuario. La velocidad solo se puede juzgar escuchando Piper en Windows.

## Sonido de inicio

En Ajustes se puede elegir una canción local (hasta 30 MB), probarla y ajustar volumen, punto de inicio, fragmento musical y volumen durante el saludo. Elegir una canción activa la reproducción al iniciar; quitarla la desactiva. El archivo se copia a `userData/music/`, no se envía por red. El sonido de inicio permanece apagado hasta elegir una canción. La reproducción real y los formatos compatibles deben verificarse manualmente en Windows.

Al abrir Bit se presenta enseguida un saludo que varía entre varias frases según la franja horaria y evita repetir exactamente el saludo anterior, mientras se prepara en paralelo el resumen hablado y visible. Piper se precarga junto con la ventana para evitar demorar el primer saludo. Si la música está activada, el fragmento elegido se repite de fondo durante la preparación y reproducción del saludo y el resumen. Su volumen baja gradualmente al comenzar la voz hasta el nivel de acompañamiento configurado; al terminar la voz, se desvanece durante cinco segundos. El resumen usa hasta diez notas Markdown locales modificadas en los últimos siete días; sin bóveda conectada o sin notas recientes, Bit lo informa sin inventar contenido. La consulta se procesa en el proceso principal con Ollama en loopback y queda registrada en `audit.log`.
